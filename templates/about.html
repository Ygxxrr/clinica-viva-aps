Como o sistema funciona

  1. O navegador envia uma requisição HTTP.

    Uma tela ou formulário solicita uma ação ao servidor.

  2. O Flask identifica a rota e valida o acesso.

    A sessão informa o usuário e seu perfil; o token CSRF protege os formulários.

  3. A camada de serviços aplica as regras.

    Valida CPF, horário, especialidade, situação e valores antes de alterar dados.

  4. O SQLAlchemy comunica com o banco.

    As classes representam tabelas. Chaves estrangeiras preservam as conexões e uma transação confirma a operação.

  5. O Jinja renderiza a resposta.

    O servidor devolve HTML atualizado ao navegador, com CSS e JavaScript para a interface.

Escolhas técnicas

Python + Flask
Código legível e rotas explícitas para facilitar a compreensão e a demonstração.
SQLAlchemy
Mapeamento objeto-relacional e consultas parametrizadas, compatível com SQLite e PostgreSQL.
Jinja + HTML + CSS + JavaScript
Interface renderizada no servidor, sem exigir um segundo projeto de frontend.
SQLite / PostgreSQL
SQLite para executar localmente; PostgreSQL externo para persistência na Vercel.
Dados e escopo
Protótipo acadêmico com dados sintéticos. Não habilitado para uso clínico real.
